# 搜索会话交互韧性修复设计

## 目标

根据 2026-08-06 的 GA4、GSC 与 Clarity 证据，优先修复已经获得搜索流量页面中的可验证交互摩擦：推荐卡片图片/标题死点击，以及游戏启动或全屏操作可能被遥测异常打断。

## 证据边界

- Google Snake Mods 是主要搜索落地页，并已产生直接试玩与全屏操作。
- Clarity 在 Google Snake Mods、Games to Play When Bored 等指南中记录了推荐图片/卡片区域死点击。
- Clarity 记录了全屏操作附近的 JavaScript 错误；代码显示遥测调用与控制逻辑处于同一执行路径，任一遥测提供方抛错都可能阻断后续状态更新。
- 不把会话摘要当作完整因果证明，不修改没有代码证据支持的 Tunnel Rush 导航或内容排名逻辑。

## 最小方案

1. 保留现有语义化本地化链接，通过卡片标记与限定 CSS 将点击区域扩展到整张推荐卡，保留键盘焦点和 reduced-motion 行为。
2. 遥测提供方分别 fail-open；Vercel、GA4 或 Clarity 任一失败都不能影响导航、开始游戏和全屏。
3. 开始游戏先更新 UI 状态再发送遥测；全屏加入重复点击锁和 Escape 退出 CSS fallback。
4. 添加 Vitest 源码回归、遥测异常单测和 Playwright 点击/全屏回退流程。

## 非目标

- 不改游戏目录、价格、评分、发布日期或搜索量数据。
- 不改 GA4/GSC/Clarity 后台设置。
- 不添加依赖，不执行 IndexNow，不改数据库或生产数据。
